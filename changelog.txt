== Changelog ==

The WordPress.org plugin page shows only the current release and the previous major
version. This file is the complete history; it ships with the plugin but is never rendered
by the plugin directory.

= 3.1.3 =

* Security: `X-Forwarded-For` is now read from the hop closest to the server. The leftmost entry is client-supplied, so a visitor could rotate it to escape the rate limiter and poison the recorded IP; trusted proxies are skipped from the right.
* Security: attachment staging and archive directories use `wp_generate_password()` (CSPRNG) instead of the predictable `uniqid()`.
* Security: deleting an inquiry resolves each attachment path with `realpath()` before the allow-list check, so a `..` segment in meta can no longer escape `uploads/ifi-inquiries/`.
* Security: stored email bodies are re-filtered with the template editor's kses allow-list before the admin detail view renders them. The same filter keeps `rgba()` colors and `{{tokens}}`; imported/historical records no longer depend on how they were originally stored.
* Security: the rate-limiter visitor cookie is marked `Secure` on HTTPS.
* New: a one-time success notice after activation with links to Email Template, Block Rules and Inquiries. It is a notice, not a redirect, so AJAX activation from the install screen is unaffected.
* New: an installation check on the plugin screens warns when the plugin folder contains more than one plugin header. That condition makes WordPress's install screen report "The plugin does not have a valid header." The check only reports; it never deletes files.
* New: `build-zip.php` refuses to build unless the package has one top-level `inquiry-form-inbox/` folder, the expected main file, and exactly one `Plugin Name` header.
* Change: uninstall now loops over every site on a multisite network; each site's options, inquiries, uploads and capabilities are removed.
* Change: `uploads/ifi-inquiries` and each record directory get an `index.php` guard as soon as the first attachment creates them.
* Change: removed the server-side file extension whitelist and `finfo` content sniff. File types are the front end's contract (`accept`); the server still enforces upload errors, per-group size limits and the file count cap.
* Change: the plugin homepage now points to the GitHub repository, and the Chinese translation of the plugin description was removed; the description stays in English.
* Breaking change: removed the legacy 1.x/2.x migration and the 3.x backfill passes. Existing `ifi_*` data is untouched; sites still on old identifiers must migrate before upgrading.
* Breaking change: upload field groups are now `files[]` (20 MB per file) and `images[]` (10 MB per file); the old business-specific group names are no longer read. Per-field caps come from the new `ifi_file_groups` filter, so changing them no longer requires editing the plugin.
* Change: the attachment summary row in notification emails no longer uses a fixed "Attachments" header. It reads the `attachments` key from Field labels; without that key the file list spans both columns. The hard-coded `row_attachments` string is gone.
* Change: notification email attachments are split by upload group (`files`, `images`) and each group uses its own Field labels entry as the header; `attachments` remains the fallback for the whole list when no group has its own label, and groups with no labels at all still render as one list. The upload group is stored in the attachment meta so archived records render the same way.
* Change: source titles are stored and displayed exactly as the frontend sends them. The `ifi_source_title_prefixes` filter and its `Article:` / `Post:` / `文章：` stripping are gone; cleaning the page title is the frontend's job.
* Fix: bulk "Move to Trash" now works on the self-rendered inquiries screen. The core `edit.php` bulk handler never runs on `admin.php?page=ifi-inquiry`, so the screen handles Trash, Restore and permanent Delete itself, using the list table's `bulk-posts` nonce and per-record capability checks.
* Change: the date and source filters no longer submit when a value is picked; both wait for the Filter button.
* Change: the source filter's empty option reads 所有来源 in zh_CN instead of 全部来源.
* Change: the View mode section is removed from Screen Options on the inquiries screen; the list has one layout.
* New: inquiry rows show a status badge after the number — New (today, not opened), Pending (opened or older), Contacted, or Spam. Closing the detail dialog marks the record as viewed, so the badge changes from New to Pending without a reload.
* Fix: the Empty Trash button on the self-rendered Trash view now permanently deletes every trashed inquiry and returns to Trash. The list form also carries the current view, so filters, search and bulk actions no longer jump back to All.
* Change: the Add button beside the language selector on the Email Template screen stays disabled until a language is chosen, and disables again when the default option is selected.
* Fix: the email status now follows the enabled/ignore matrix — with auto-confirmation off it warns even when nothing failed, with it on it warns only for failed sends, and "Ignore unsent warning" suppresses both cases.
* Fix: the activation hook is registered from the main plugin file, which is the location WordPress documents, instead of from the class initializer.

= 3.1.2 =

* Change (zh_CN): the first submenu item under Inquiries reads 所有询盘 instead of 全部询盘, matching the dashboard's 查看所有询盘 and the detail back link. The browser title is still Inquiries; no option or string key changed.
* New: the two rate-limit thresholds are editable on the Block Rules screen — `rate_minute` and `rate_hour`, defaulting to the 3 per minute and 10 per hour the plugin has always enforced. The windows themselves stay fixed at 60 seconds and one hour; 0 turns a window off. Existing sites keep their behaviour until someone changes the number, and `ifi_rate_limits` still wins over both fields, including the window length.
* Change: the per-rule counters on the card headers are gone. A single 30-day number next to "Honeypot" answered a question the stats strip already answers in full ("N blocked in the last 30 days", broken down by rule), and it made the header row taller than the other cards for no benefit.
* Fix: the rate-limit line that used to sit inside "Network and duplicates" is now a proper card with two inputs, so a number that can be changed no longer reads like documentation.

= 3.1.1 =

* New: the dashboard widget opens an inquiry in place. Clicking a name went to All Inquiries and popped the dialog there, which lost the dashboard context and cost a page load; the dialog now opens on the dashboard itself, and Previous/Next steps through the widget's recent list instead of the whole inbox.
* New: the honeypot's hidden field name is editable on the Block Rules screen. It was a read-only `companyWebsite` that only the `ifi_honeypot_field` filter could rename — a frontend that posted a different name had no way to say so without code. Sites that already rename it in code keep winning; only then does the screen show the name actually in effect, instead of pretending the input works.
* Change: the honeypot field name is normalised to `[A-Za-z0-9_-]`, the same character set the REST collector keeps. Anything else would never match the key the form posts, so it is stripped; an empty result falls back to `companyWebsite`.
* Fix: the honeypot field name cannot reuse one of the form's own fields (`fullName`, `email`, `message`, `pageTitle`, `timezone`, …). A required field would 400 every submission; an optional field such as `pageTitle` is non-empty on real inquiries, so the honeypot would have silently swallowed all of them. The value falls back to `companyWebsite` and the screen explains why.
* New: the Block Rules screen states the built-in rate limits — 3 per minute and 10 per hour per visitor, HTTP 429 beyond that. They were always enforced, but nothing in the admin said so; the first sign was the eleventh inquiry failing.
* New: the `ifi_rate_limits` filter. The two windows were private constants with no way to tune them, which is too rigid for a B2B site where twenty colleagues share one office IP. `limit` 0 turns a window off; a malformed value falls back to the default instead of locking the site.
* Change: the dashboard's "View all inquiries" link reads 查看所有询盘 in zh_CN, matching the "All Inquiries" menu and back link.
* Change: the detail dialog is only printed for users who can view inquiries. The dashboard is visible to every account, and it was printing an empty skeleton with a nonce for users who could not open it.

= 3.1.0 =

* New: the form type recognises five styles — page, popup, drawer, floating and sticky. The Source column, the `{{form_type}}` placeholder and the overview board all use the right name.
* New: the `ifi_form_variants` filter. Your frontend can post any `formVariant` slug; register it here to give it a display name without touching the plugin. Unregistered slugs are stored and shown as they were sent, so a frontend can ship a new form style before the site is updated.
* New: the Form type card lists every style that actually has inquiries, and shows a dash when there are none — the same empty state as the Sources and Languages cards. It used to render two rows of zeros on an empty inbox.
* Change: `{{form_type}}` falls back to "Page form" only when no `formVariant` was sent. Unknown slugs are now rendered as sent instead of being labelled a page form.
* Fix: the `{{time}}` placeholder in both emails printed a UTC clock labelled with the site timezone. `date_i18n()` treats a passed timestamp as already offset; `wp_date()` uses the real one, so a +8 site no longer shows a time 8 hours early next to a correct "local time" line.
* Change: the Languages and Form Type cards now match Sources — three rows visible, the rest scrollable; the redundant "more languages" hint is gone.
* Change: there is no "Other" bucket in the Form Type card. Empty `formVariant` values (records from before 3.0) count as Page form; unregistered slugs get their own row labelled by the slug, exactly as the Source column shows them.
* Change: the monthly sparkline labels follow the admin's language. A Chinese admin on an English site used to see Jan/Feb; it now reads 1 月 … 12 月.
* Change: English card titles are Title Case ("New Today", "Emails Sent", "Monthly Trend", "Form Type"). Same for "Send Test Email", "Mark as Contacted", "Reply", "Reply Template", "Inquiry Notification Template" and "Auto-Confirmation Template".
* Change: the detail dialog's side panel now uses the list's column names (# / From / Attachments / Source / Delivery status / Received) instead of its own Email / Emails / Submitted.
* Change: the first list column is 24% wide so View | Mark as Contacted | Trash fits on one line; row actions no longer wrap.
* Fix: the Add Media button carried WordPress's `insert-media add_media` classes, which opened a second media frame behind ours — two clicks to close and an "Insert into post" button. It now opens a single frame with an "Insert" button.
* Fix: zh_CN wording — "全部询盘" → "所有询盘" and the Trash row action → "移至回收站", following WordPress core; the three new form styles are 抽屉/悬浮/固定表单 (no "式").
* Change: "Mark as pending" → "Mark as Pending" in English.
* Change: removed the `embedded` form style and stopped showing unregistered slugs in the Form Type card. A custom slug is still accepted and stored, and the Source column still shows it; it just no longer looks like a sixth official style.
* Change: the Add Media button keeps the `add_media` class (that is where WordPress puts the dashicon) but no longer has `insert-media`, so core's second click handler is gone — one frame, one click to close.
* Change: hovering the form-type bar no longer hides the percentage labels.
* Change: the detail side panel's heading is now the inquiry number (#); "From" shows name + email like the list column.
* Change: inquiry numbers use the `IQ-` prefix — `IQ-20261125001` instead of `IN-20261125001`. The date and the 3-digit daily sequence are unchanged, and records already issued keep their number. The prefix lives in one constant, so it is changed in one place again next time.
* Change: every row in the Form Type card carries the same colour swatch as its segment in the bar below, so the list and the bar read as one thing.
* Change: the Languages card names locales the way the current admin language names them — `en-US` reads 英语（美国） in a Chinese admin, English (United States) in an English one. The names ship with the plugin (`includes/class-ifi-locale.php`) because `intl` is missing on a lot of hosts and WordPress's own locale list only carries native names.
* Fix: "Ignore unsent warning" used to hide the entire Email Problem card, which also hid failed inquiry notifications. It now only keeps unsent auto-confirmations out of the count; the card stays and still reports notification failures.
* Fix: permanently deleting an inquiry could leave files behind. Attachments whose archiving failed stay in the PHP temp folder (`ifi-stage-*`), outside `uploads/`; those are now removed too, and the record's own folder is swept by its `{ID}-` name in case the meta list is incomplete.
* Change: every date and time the plugin prints — list "Received", detail dialog, dashboard widget, sparkline tooltips and both emails — follows the site's Date Format and Time Format settings instead of a hard-coded `Y-m-d H:i` / `g:i a`.
* Fix: `{{time_local}}` in the reply template was always empty. The visitor timezone is stored in post meta, not in the field values the template receives, so the lookup now falls back to the meta.
* Change: the `#` column is a fixed 218px — enough for `View | Mark as Contacted | Trash` (or 查看 | 标记为已联系 | 移至回收站) on one line. As a percentage it grew to 305px on a wide screen and shrank to 168px on a laptop, where the last action was clipped.
* Fix: the Trash view in the list's status links reads 回收站 again; the row action keeps 移至回收站. Both are "Trash" in English, so they are two gettext contexts of the same msgid rather than one shared translation.
* Change: the WordPress dashboard widget is rebuilt on the plugin's own vocabulary — four KPI tiles (New Today, Pending, Spam, Email Problem) plus recent inquiries showing number, sender, source with form style, delivery chip and received time. The old date-column layout, its status dots, its two summary strings and its CSS are gone.
* New: a "Not Spam" row action on blocked inquiries replaces "Mark as Contacted" — a blocked record was never delivered, so marking it contacted made no sense. The action clears the spam marker and moves the record back to the normal list.
* Fix: blocked inquiries were archived with the raw message as post body, so View showed a plain-text paragraph instead of the email card. They now use the same `build_body()` template rendering as normal inquiries (no mail is sent).

= 3.0.0 =

* Breaking change: the plugin is now Inquiry Form Inbox for Headless WordPress. Folder, main file, text domain, classes, traits, post type (`ifi_inquiry`), meta keys (`ifi_inquiry_*`), options (`ifi_*`), capabilities (`ifi_*_inquiries`), admin actions, nonces, CSS classes, and attachment directory (`uploads/ifi-inquiries/`) all use the new `ifi` prefix. A one-time migration moves data from 2.x (`eln_*`) and 1.x (`inquiry`) automatically. Back up before upgrading.
* Breaking change: the REST namespace is now `inquiry-form-inbox/v1`. The `email-log-notifications/v1` and `site-inquiries/v1` namespaces were removed. Update your frontend.
* Breaking change: all developer hooks moved from `eln_` to `ifi_` (`ifi_recipient`, `ifi_max_files`, `ifi_required_fields`, `ifi_length_limits`, `ifi_dashboard_limit`, `ifi_strings`, `ifi_field_manifest`, `ifi_autoreply_sent`).
* New: the inquiry list columns are now # / From / Message / Attachments / Source / Automatic Status / Received. The automatic status collapses both emails into one badge: All Sent, Only Notification, Only Auto-Confirmation, or Not Sent.
* New: New / Contacted views with counts, and a "Mark as contacted" row action that can be undone ("Mark as new").
* New: a collapsible "Overview" board sits at the top of the inquiry list — new-inquiry count, "N not sent" warning, 7/30-day submission volume with the change against the previous period, top visitor languages, page-vs-popup form split, and per-source submission counts (top five, each linking to the filtered list). It can be collapsed, and the state is remembered per browser.
* Change: the default email templates were redesigned to match the WordPress admin style — light grey canvas, white card, `#dcdcde` borders, `#2271b1` accent, system fonts, English copy. Saved custom templates are left untouched; clear the HTML source to fall back to the new defaults.
* Change: the plugin file no longer ships a compatibility layer for 1.x admin actions.

= 2.0.3 =

* Fix: attachments could be delivered by email but never appeared in the admin. Archiving the staged upload used a bare `rename()`, which fails with `EXDEV` whenever the PHP temp directory and `wp-content/uploads` sit on different mounts — typical on shared hosting. The code then silently kept the temp path, which has no public URL, so the inquiry detail showed “—”. Archiving now falls back to `copy()` + unlink.
* Fix: `persist_attachments()` always returns the same `name / path / url / size` shape, including when the archive directory cannot be created. Previously a failed `wp_mkdir_p()` returned the staging entries, which have a different shape.
* Improvement: attachments that could not be archived are still listed by name and size in the inquiry detail, with an explanatory tooltip, instead of being hidden.

= 2.0.2 =

* Fix: submissions with attachments were always rejected with "File type .xxx is not allowed." `wp_check_filetype_and_ext()` expects a map of `extension regex => mime`, but it was given a plain list of extensions, so its internal regex became `\.(0)$` and every upload resolved to `ext = false`. Plain-text inquiries were unaffected, which made it look like a host problem.
* Fix: file type detection now uses `wp_check_filetype()` against a proper extension/mime map, and a `finfo` content check rejects PHP/HTML payloads disguised with an allowed extension. CAD formats (`.step`, `.dwg`, `.dxf`) are no longer rejected when the host's `finfo` reports them as `text/plain`.

= 2.0.1 =

* Compatibility: moved constants out of traits. Trait constants need PHP 8.2, so on a host still pinned to PHP 8.0/8.1 the plugin file failed to compile and the whole plugin was dead on arrival (locally perfect on 8.3+). The plugin header has always said `Requires PHP: 8.0`; now the code actually is.
* Fix: rate limiting no longer collapses every visitor into one bucket when the site sits behind a reverse proxy that is not on the trusted list. That is the normal setup when the marketing site proxies `/wp-json` to WordPress — the proxy's own IP was used as the visitor identity, so the 4th submission inside a minute returned 429 for everyone. Requests that arrive through an unknown proxy now fall back to the signed visitor cookie (one bucket per visitor).
* New: trusted proxies can be configured with `define( 'IFI_TRUSTED_PROXIES', array( '203.0.113.10' ) )` in `wp-config.php`, in addition to the `ifi_trusted_proxies` filter.

* Security: removed a server-side HTTP request driven by visitor-supplied URLs (SSRF).
* Security: inquiry detail and delete now use object-level capability checks.
* Security: hardened rate limiting, upload validation, inline script encoding, and preview sandboxing.
* Engineering: split the monolithic plugin into focused modules, externalized CSS/JS, and added uninstall and privacy support.
* I18n: replaced the built-in three-language array with WordPress gettext and bundled POT/PO/MO files.
